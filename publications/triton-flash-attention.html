Triton Flash Attention Kernel Walkthrough: The Forward Pass

09-24-2025

So you’ve learned about basic Triton language primitives like make_block_ptr, but how does it fit into a real, high-performance GPU kernel?

The goal of this article is to understand the why — the design decisions that make FlashAttention fast by aligning computation with the GPU memory hierarchy.

Background: The FlashAttention Intuition

Standard attention computes an \( n \times n \) attention matrix. For large \( n \), this matrix does not fit in SRAM, forcing constant reads and writes to HBM. 


def parallel_attn(q, k, v):
    # Prepare launch parameters
    return ParallelAttentionFunction.apply(q, k, v)

The key idea behind FlashAttention is tiling: we never materialize the full matrix. Instead, we compute attention block-by-block.

Mathematically, we are still computing:

\[ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V \]
